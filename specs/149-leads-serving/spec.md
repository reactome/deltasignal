# Feature Specification: Serving the Curator-Drawn Leads

**Feature Branch**: `specs/149-leads-serving`

**Created**: 2026-11-07

**Status**: Draft

**Input**: Adam approved the label ("that label seems fine", 2026-11-07) after specs/148 measured the diagram-arrow bridges: on readouts a pathway alone cannot reach, the drawn bridges beat always-no-change on balanced accuracy (full arm: +0.0503 [+0.0216, +0.0784], n = 2,871), with one measured mechanism (a bridged p-AKT "down" is right 24%) and eleven canonical-but-unrated arrows. Serve those answers where the product today says only "not reached here" — as leads, labelled, never merged.

## The serving design (fixed before implementation)

1. **The composites ride the existing, validated endpoints.** The 11 specs/148 composite bundles ship in the served catalog under non-listed names (`ctx-arrows_R-HSA-<id>`): `parse` accepts any catalog directory, the pathway picker's listing regexes skip the prefix, and pins/solve/readouts work unchanged. No new solve-path code.
2. **`GET /api/leads`** serves `src/api/leads.json` verbatim (the scope-statement pattern: versioned, provenance-carrying, honest refusal on a missing/malformed file): per centre pathway — the composite's catalog id, each arrow (source pathway name, entity name, drawn in release 97), and the measured rate class (`measured` with the specs/148 numbers for the p-AKT arrows; `unrated` otherwise), plus the registration (build ids, arm, spec).
3. **The client flow (its own WebsiteAngular spec)**: after a solve whose readout is `untouched`, if the pathway has a lead composite, the client runs the same perturbation through `ctx-arrows_<id>` (parse → pins → solve → readouts for the untouched ids) and shows the result in the "not reached here" slot as: "Lead, via <source pathway> (curator-drawn): <call> — down-calls like this were right 24% on the record" or "— no measured rate yet". Never in the main table's call column; never unlabelled.

## Functional Requirements

- **FR-001**: `/api/leads` additive, scope-pattern: provenance-complete file enforced by a repo test (every arrow carries source, entity, centre, release, rate class; every measured rate carries the arm and spec); allow-listed refusal when unreadable.
- **FR-002**: The composite bundles enter the catalog without appearing in `/api/pathways` (a unit test pins the listing exclusion) and parse/solve/readouts on them behave as any bundle (one happy-path API test through a composite fixture).
- **FR-003**: No change to any existing endpoint's response.
- **FR-004**: The catalog packaging is recorded: the composites are copies of build `20261107-arrows97-11c`'s centre dirs; `scripts/catalog.sh` is untouched (composites are shipped beside a build, not generated by it) — a follow-on catalog-tooling spec owns automation if the class earns it.

## Non-goals

- No UI work in this repo (the WA spec follows once served).
- No automatic composite generation in catalog.sh (manual packaging for 11 dirs now; tooling later if adopted).
- No rate invention: `unrated` stays `unrated` until a dataset perturbs upstream of an arrow.
- No release-98 content (the coordinated upgrade is its own plan).
